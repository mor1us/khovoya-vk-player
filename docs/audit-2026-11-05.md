## 1. Что не работает (по убыванию важности)

### 1.1 Капча ВК: ответ теряется, запрос висит вечно
`src/main/index.ts:76-83`

```ts
onCaptcha: async (sid, img) => {
  ...
  return new Promise<string>((resolve) => {
    handle('vk:captchaAnswer', (key: string) => { resolve(String(key ?? '')) })
    win!.webContents.send('vk:captcha', { sid, imageDataUrl })
  })
}
```

Три проблемы в одном месте:

- `handle()` (`src/main/ipc/handlers.ts:21`) первым делом делает `ipcMain.removeHandler(ch)`. Если ВК попросит
  капчу второй раз, пока первая не отвечена, — `resolve` первой теряется навсегда, и её `VkClient.call`
  зависает до конца сеанса.
- Нет таймаута и нет отмены при закрытии окна капчи. Закрыл модалку не кнопкой «Отмена» (например, упал
  интерфейс) — запрос висит.
- Если `win === null` или картинка не скачалась, возвращается `''`: ВК снова ответит ошибкой 14, и так до
  `attempt < 4` в `src/main/vk/client.ts:49` — вместо понятного «капча не показалась».

Плюс рядом стейл-комментарий «ответ придёт в Task 10» — задача давно сделана.

**Как починить:** регистрировать `vk:captchaAnswer` один раз при старте, держать текущий `resolve` в
переменной (`let pendingCaptcha: ((k: string) => void) | null`), добавить таймаут (например, 3 минуты) и
сбрасывать ожидание при `win.on('closed')`.

### 1.2 Ошибка в `setup()` — и приложение запускается без окна
`src/main/index.ts:236`

```ts
app.whenReady().then(async () => { await setup(); win = createWindow(); attachWindow(win); ... })
```

`setup()` не обёрнут в try/catch. Любая его ошибка (в MOCK-режиме — `startMockMedia`, в обычном —
`jsonFile`/`settings` на битом JSON или без прав) → процесс жив, окна нет, трея нет, пользователь видит
«ничего не произошло», и в журнал ничего не попадает.

**Как починить:** `try { await setup() } catch (e) { log(...) }` и всё равно создавать окно; либо
`dialog.showErrorBox` с текстом и выход.

### 1.3 Незащищённый `JSON.parse` ломает интерфейс и поиск
`src/renderer/ui/TopBar.tsx:31` и `src/renderer/store/ui.ts:41`

```ts
const hist: string[] = focus && !query ? JSON.parse(localStorage.getItem('searchHistory') ?? '[]') : []   // в render!
...
const hist = JSON.parse(localStorage.getItem('searchHistory') ?? '[]') as string[]                        // в submit()
```

Если `searchHistory` окажется битым (обрыв записи, ручная правка, другая версия формата), первый парс падает
прямо в рендере `TopBar` → весь интерфейс уходит в «Что-то сломалось» (`src/renderer/main.tsx:18`), а второй
ломает любой поиск. Все остальные чтения localStorage в проекте обёрнуты в try/catch — эти два забыли.

**Как починить:** общий хелпер `readJson<T>(key, fallback)` и использовать его во всех местах (их сейчас 8:
`player.ts:64`, `history.ts:5`, `mixes.ts:13-14`, `wave.ts:34,38`, `sourceNav.ts:5`, два выше).

### 1.4 Дубль IPC-канала `win:close`
`src/main/index.ts:189` и `src/main/ipc/handlers.ts:51` регистрируют один и тот же канал с одинаковой
логикой. Второй вызов просто перетирает первый (`removeHandler`). Работает, но один из них — мусор, и при
расхождении логики будет трудноуловимый сюрприз: сработает тот, что зарегистрирован позже.

### 1.5 `TokenKeeper`: при отвалившейся сети — поток повторных запросов
`src/main/auth/webToken.ts:40-47`

При сетевой ошибке возвращается старый ключ, но `this.at` не обновляется. Значит следующий же вызов API
снова пойдёт за ключом — и так на каждый запрос, пока сеть не вернётся. При обрыве связи это десятки
лишних попыток в минуту.

**Как починить:** при сетевой ошибке ставить `this.at = this.now() - REFRESH_MS + 30_000` (пауза 30 с).

### 1.6 `scLog` используется выше объявления
`src/main/index.ts:115` использует `scLog`, объявленный `const` на `:129`. Спасает только то, что это
колбэк и вызовется позже. Любая правка, которая вызовет его синхронно, даст `ReferenceError`.

### 1.7 `FALLBACK_SC.sort(...)` портит общий массив
`src/renderer/store/wave.ts:143`

```ts
(top.length ? top : FALLBACK_SC.sort(() => cryptoRandom() - 0.5).slice(0, 3))
```

`Array.sort` сортирует **на месте** → порядок модульной константы `FALLBACK_SC` меняется навсегда.
Плюс `sort(() => rnd() - 0.5)` — перекошенная тасовка; в проекте уже есть честный `fisherYates`
(`src/renderer/player/shuffle.ts:11`), но в `wave.ts` трижды (`:120`, `:132`, `:143`) используется именно
кривой вариант.

### 1.8 Волна ВК молча ничего не делает при пустом результате
`src/renderer/store/wave.ts:210-217`: `start()` при `b.length === 0` просто выходит — ни сообщения, ни
тоста. А `startKind()` для SoundCloud в том же случае (`:201-204`) честно бросает понятную ошибку.
Нажал «Волна ВК», ничего не собралось — на экране ничего не изменилось.

## 3. Чтобы со мной было быстрее работать

1. **Нет `CLAUDE.md`.** Каждый новый разговор я заново выясняю: electron-vite, `npm run dev:mock`,
   `npm test` = vitest, где главный процесс, что ключи нельзя логировать, что текст в интерфейсе —
   по-русски и на «ты». Один файл на 20-30 строк экономит это каждый раз.
2. **Нет ESLint**, хотя в коде пять `// eslint-disable-line react-hooks/exhaustive-deps`
   (`PlaylistPage.tsx:27`, `Queue.tsx:21`, `Similar.tsx:40`, `ScComments.tsx:18`, `Waveform.tsx:21`).
   То есть правила отключают, а самих правил нет. Неиспользуемый `_extra`, дубль условия в `sourceNav.ts`
   и `sort()` на константе — это всё находит линтер.
3. **IPC не типизирован.** `handle(ch: Channel, fn: (...a: any[]) => unknown)` — канал проверяется, а
   аргументы и результат нет. Карта вида `type IpcMap = { 'vk:search': [[q: string, off?: number], SearchResult] }`
   дала бы автодополнение и ловила бы расхождения между `handle(...)` и `window.api.invoke<T>(...)`
   (сейчас тип результата пишется руками на каждом вызове и ничем не связан с главным процессом).
4. **`any` в 39 местах.** На границе с API ВК/SoundCloud это нормально, но стоит прогонять ответы через
   маленькие функции-парсеры (как уже сделано в `mapTrack`/`mapScTrack`) и не пускать `any` дальше.
5. **Node.js на машине не установлен** — нет ни `node`, ни `npm`, ни nvm/fnm/volta/scoop/choco.
   Без него не ставятся зависимости, не идут тесты (33 файла), typecheck и сборка. Пока это не решено,
   любые мои правки проверить нечем.
